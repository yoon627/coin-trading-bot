# Decisions

## 배경 — 중복 작업을 닫고 차이분만 가져왔다

같은 그룹핑 버그를 다른 브랜치(`sell-strategy-attribution`, PR #117)가 먼저 고쳐 머지됐다. 그쪽이 `BuySide`
캡슐화·전략 귀속까지 처리해 더 정교하므로 내 PR #119 는 닫았다. main 에 없는 개선만 여기서 다시 올린다.

## 1. 부분 청산도 매도 정보를 노출한다

현재 `roundTrip()` 은 `closed`(잔량 0) 가 아니면 `exitAt`·`exitPrice`·`sellAmount`·`pnlPercent` 를 전부 null 로
비운다(`TradeRoundTrip.kt:134,147-150`). 그래서 **이미 실현된 매도가 화면에서 통째로 사라진다** —
"10개 사서 4개 팔고 6개 보유 중"이 "10개 사서 보유 중"으로만 보인다.

→ 매도 기록이 있으면(`sells.isNotEmpty()`) exit 값을 채운다. 상태는 셋으로 가른다:
`open`(매도 없음) / `partiallyClosed`(매도 있고 잔량 남음) / 전량 청산.

## 2. 손익은 판 만큼의 원가만 차감한다

현재 `pnlAmountGross = sellAmount − buyAmount`(`:152`)는 **아직 팔지 않은 매수분까지 손실로 친다.**
`BUY 10개(1000원) → SELL 4개(480원)` 이면 `−520원` 이 된다. 실제로는 `480 − 평단100×4 = +80원` 이다.

→ `sellAmount − entryPrice × sellVolume`. 전량 매도면 기존과 같은 값이라 회귀가 없다.

## 3. 초과 매도는 손익을 계산하지 않는다

수동 `sellAll` 은 거래소 잔고 전체를 팔아 이전 포지션의 잔여분까지 매도 수량에 들어간다. 그러면
`sellVolume > buyVolume` 이 되고, 그 잔여분의 원가가 이 그룹에 없어 손익이 부풀려진다.
현재는 `remaining()` 이 음수라 `closed=true` 가 되고 `sellAmount − buyAmount` 가 그대로 나간다.

→ 초과 매도면 `partial` 로 표시하고 손익 금액을 비운다(모르는 값을 채우지 않는다는 기존 원칙과 같다).
