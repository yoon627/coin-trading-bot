# Goal

[[take-profit-stop-loss-2026-09]] 가 남긴 병목은 계기 해상도다 — 익절 8·off 의 우위는 240분봉이 트레일링을 덜 걸어 생기는 편향과 같은 방향이고,
손절 축은 진입 봉 안의 순서(저가가 돌파 전인지)를 240분봉이 말해 주지 않는다. 사용자 판단("시간 단위를 줄여 분봉으로 보는 게 맞지 않나")대로
**같은 10창을 15분·5분봉으로 다시 재어** 해상도가 오를수록 우위가 어디까지 줄어드는지를 본다. 초봉은 Upbit 가 최근 3개월만 제공해 과거 창에 쓸 수 없다.

같은 데이터로 9시 변형 — **손실 포지션만 09:00 에 정리하고, 트레일링 손절선이 진입가 위로 잠긴 이익 포지션은 트레일링이 걸릴 때까지 유지**(상한 5거래일) — 도 판정한다.
익절 5% 상한과 09:00 강제청산이 이익 포지션을 자르는 같은 메커니즘이라 두 질문의 교차점이다. 단 09:00 축은 이것이 **세 번째 관측**이다 —
[[hold-limit-policy-2026-09]] 가 이미 (1) 거울상 정책(`holdLimitOnlyWhenProfitable` = 손실이면 넘김)을 13정책 중 유일하게 홀드아웃에서도 못 이기는 것으로 기각했고,
(2) 연장 2·3·5·10일 계열은 "잔여를 하루 더 들면 같은 마켓의 다음 진입을 막는다"는 기회비용으로 현행에 못 미쳤다. **결과 전 예측**: 이번 정책도 같은 기회비용을 진다 —
유지된 포지션이 막는 진입 수를 보고한다(§Acceptance 8).

라이브 파라미터는 바꾸지 않는다. 이 브랜치는 `tp-sl-grid`(미머지) 위에 쌓였다 — 하네스(`PairedMaxTBootstrap`·`LiveSemanticsArm` 옵션)를 재사용한다.

# Decisions

## 1) 해상도 사다리 — 판정은 가장 촘촘한 5분봉, 240·15 는 추세

편향은 해상도가 오를수록 줄어들 뿐 0 이 되지 않는다(라이브는 10초 tick). 그래서 "5분에서 통과" 만으로는 부족하고, **15 → 5 에서 우위가 얼마나 줄었는지**가
남은 편향의 크기를 알려 준다. 수렴 기준을 사전고정한다(§Acceptance 5). **수렴은 tick 편향의 소멸 증명이 아니라 가정**이다 — 그래서 비관 트레일링 브래킷(§Acceptance 6e)을
함께 요구한다.

## 2) 세 rung 은 같은 거래 집합을 재지 않는다

진입 체결가는 `max(돌파선, 봉 시가)` 이고 신호 window 의 당일 부분봉은 직전 봉까지의 누적이라, 봉이 짧을수록 체결가는 돌파선에 가까워지고 부분봉이 달라져
**진입이 생기거나 사라진다**(돌파선 자체만 해상도 불변). 그래서 rung 마다 기준선 거래수·Σpnl 이 다르고, 격차/기준거래 의 분모는 **그 해상도의 기준 거래수**다.
수렴 비율은 "트레일링 편향 감소"와 "진입 체결 개선"이 섞인 값이다 — rung 간 진입일 집합 겹침 수를 보고한다.

## 3) 9시 정책은 진입 집합을 바꾼다 — 페어링을 거래가 아니라 진입일 단위로

이익 포지션이 다음 날까지 살아 있으면 그 마켓의 다음 진입이 막힌다. 기여를 **진입일 단위**(그날 진입한 거래 손익 합의 차)로 잡으면 같은 frame·같은 재추출·같은 maxT 를
그대로 쓸 수 있고, 익절·손절 셀에서는 거래 페어링과 정확히 같은 값이 된다. 노출(Σ보유일)이 다르므로 격차/기준거래 만으로는 부족하다 — §Acceptance 6(f).

## 4) 240분봉 관측(smoke) 이후에 확정·수정한 규칙 — 열거

smoke 가 규칙 작성 뒤에 돌았지만 그 순서는 제3자가 검증할 수 없다. 그래서 **240분봉을 non-blind 로 취급**하고, 관측 뒤 손댄 항목을 전부 적는다:
(a) family 를 선행 19셀에서 7셀로 좁힌 것(q 2.644 → 2.457 로 통과가 쉬워진다 → 5분 판정표에 선행 q 2.644 기준 통과 열 병기),
(b) 수렴 미정의(15분 격차 ≤ 0) → 후보 불가로 확정, (c) 비단조(240 < 15) → 승격 불가 추가, (d) 노출 정규화(§6f) 추가, (e) 공통 frame(§4) 확정,
(f) 비관 트레일링 브래킷 조건(§6e) 추가, (g) 결측 봉 규약(§7) 확정. 정책 정의(`keepWinnersUntilDays=5`, 잠김 = 트레일링 손절선 > 진입가, gross)와 7셀 구성은 smoke 전과 같고 이후 변경 금지.

## 5) 이 계기의 편향 방향 (결과 보기 전)

- 익절 축: 넓은 쪽 단방향(트레일링 과소 발동) — 브래킷 = `pessimisticTrailing`(이 봉 고가까지 고점에 포함, 진입 봉 제외).
- 손절 축: 양방향(진입 봉 저가 순서 / 임계선 무슬리피지 체결) — 브래킷 = `entryBarStopOnClose`, 체결가 편향은 오버슛으로 크기만.
- **9시 정책 셀: 유리한 편향이 하나 더 있다.** 트레일링 체결가는 봉 저가가 손절선을 얼마나 관통했든 손절선 그대로다(무슬리피지·무갭). 포지션을 최대 5일 더 들고 있으면
  갭 관통 노출이 기준선보다 크다. 브래킷 없음 — 갭 관통 건수(청산 봉 시가 < 손절선)와 오버슛을 보고한다.

# Acceptance

**아래 1~11 은 15·5분봉 결과를 보기 전에 커밋한다. 240분봉 rung 은 smoke 로 이미 관측됐다(Progress·Decisions 4). 실행 후 문구를 고치지 않는다.
배관 단정이 실패하면 배관을 고쳐 같은 규칙으로 재실행한다 — 단 결측 봉·보유일은 7 에 규약이 있으므로 그 자체는 실패 사유가 아니다.**

1. **계기** = `LiveSemanticsArm`(진입 장중 돌파 즉시, 청산 `IntrabarExitModel`) — 봉 단위만 240·15·5분. 기준 = 현행 라이브
   `StrategySearchGrid.currentLivePoint()`(TP 5 / SL 5 / 트레일 1.5 / arm 0 / k 0.5 / h 1). 창 = [[take-profit-stop-loss-2026-09]] 과 같은 10창(시간순), 워밍업 50일.
   15·5분 캐시가 한 마켓이라도 없으면 판정하지 않는다(부분 캐시 금지).
2. **후보 family = 7셀**(rung 마다 같은 7): 익절 축 `TP8/SL5`·`TPoff/SL5`, 손절 축 `TP5/SL3`·`TP5/SL7`·`TP5/SLoff`,
   9시 정책 `TP5/SL5+keep5`·`TPoff/SL5+keep5`(`keepWinnersUntilDays=5`: 트레일링 손절선 `peak×(1−0.015)` 가 진입가(gross) 위로 잠긴 포지션만 09:00 을 넘겨 유지,
   진입 +5 거래일(일봉 index 차) 첫 봉에서 강제 청산). 이 정의와 구성은 이후 변경 금지.
3. **기여** = **진입일 단위** — 창 w 의 날짜 d 에 `Σ(그날 진입한 셀 거래 net pnl%) − Σ(그날 진입한 기준 거래 net pnl%)`. 익절·손절 셀은 거래 1:1 페어링과 같은 값(진입 집합 동일 — 단정),
   정책 셀은 진입 집합이 달라도 정의된다. **격차/기준거래 의 분모 = 그 해상도의 기준 거래수**(240분에서 1,058건, 15·5분은 다를 수 있다).
4. **frame = 240분봉 기준 공통 frame**(창별 워밍업 이후 240분봉이 있는 거래일, 창당 150일·합 1,500일·결측 마켓-일 0 — 단정) 을 세 rung 이 공유한다.
   15·5분봉에서 봉이 있는 날은 그 부분집합이다. 재추출 = 창별 stratified 이동블록 L=5, B=20,000, seed 고정, **셀·rung 공통 draw**(한 번의 `resampleSums`).
   판정 = 단일단계 maxT(FWER 5%), 통과 = 동시 95% 하한 > 0, rung 마다 별도 family·q. 단일 배열 구간 = 재중심화 2.5/97.5 백분위. 보고 전용: L=10 통과 열, 선행 q(2.644) 기준 통과 열.
5. **주 판정 = 5분봉. 수렴** = 5분 격차/기준거래 ≥ 0.8 × 15분 값 **그리고** 15분 값 > 0. 15분 값 ≤ 0 이면 "수렴 미정의" 로 후보 불가.
   **비단조**(240분 값 < 15분 값, 15분 값 > 0 일 때)면 "편향 단조감소 반증" 으로 후보 불가(240 은 게이트가 아니라 반증 조건에만 쓴다).
