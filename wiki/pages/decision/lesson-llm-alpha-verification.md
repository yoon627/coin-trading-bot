# LLM 알파 검증

"LLM 을 트레이딩 판단에 붙이면 수익이 나는가" 는 주기적으로 다시 떠오르는 질문이다. 이 페이지는 그 질문을 **어떤 순서로 답해야 하는지**를 고정한다. 결론은 하나다 — **과거 데이터 백테스트로는 답할 수 없고**, 그 사실이 검증 설계 전체를 결정한다.

## 무엇이 기각됐고, 무엇이 기각되지 않았나

[[rightsizing-history]] 가 기록한 제거 사유는 이렇다:

> ML·스캘핑·Claude 분석은 **수익 기여가 입증되지 않은 채** 유지비만 발생했다.

이건 **미검증**이지 **반증**이 아니다. 효과가 없다고 증명된 게 아니라, 증명한 적이 없는데 비용이 났다는 뜻이다. 문은 닫혀 있지 않다 — 다만 재도입하는 쪽에 **입증 책임**이 붙는다.

원래 구현이 무엇이었는지는 알 수 없다. `git log --all --diff-filter=D` 로 231개 커밋 전체의 삭제 파일 경로를 훑어도 LLM 관련 경로가 나오지 않는다(현재 히스토리 이전에 제거됨). **무엇이 실패했는지 모르므로, 같은 실패를 피했다고 주장할 근거도 없다.** 재도입 설계는 과거 구현을 개선하는 형태가 아니라 처음부터 세워야 한다.

## LLM 이 정보를 더할 수 있는 자리는 텍스트뿐

기본 전략 `combined` 의 세 조건은 **전부 가격·거래량 파생**이다([[swing-strategies]]) — 변동성 돌파 목표가, 5/20 MA 추세, RSI 14. 지표는 가격의 결정론적 함수다.

여기서 갈리는 두 방향 중 하나는 확실히 무의미하다:

- **가격 데이터를 LLM 에 재입력** — 같은 정보를 더 비싸고, 더 시끄럽고, 재현 불가능하게 재계산하는 것이다. 지표의 열등한 구현이며 새 정보량이 0 이다. 같은 이유로 **"LLM 으로 지표를 예측"하는 설계도 성립하지 않는다** — 지표를 예측한다는 건 가격을 예측한 뒤 한 단계 정보를 잃는 것과 같다. 예측할 것이라면 지표를 우회하지 말고 수익률·방향을 직접 예측해야 한다.
- **가격에 아직 반영되지 않은 텍스트** — 거래소 공지(상장·유의종목·상폐), 규제 이벤트, 프로젝트 공시. 이것만이 지표가 구조적으로 볼 수 없는 축이다.

D1 스윙이라는 시간축은 여기서 **유리하게** 작용한다. LLM 응답 지연이 수 초~수십 초여도 제약이 되지 않는다. 더 짧은 타임프레임이었다면 성립조차 하지 않을 설계다.

현재 텍스트 수집 경로는 **없다** — `common`·`bot/src/main` 에 공지·뉴스 수집 코드가 없고, [[persistence-schema]] 에도 텍스트 테이블이 없다. 시세 시계열만 쌓인다([[marketdata-pipeline]]).

## 백테스트로는 증명할 수 없다

이 절이 이 페이지의 핵심이다. 장벽 셋 중 ②가 결정적이다.

**① 과거 텍스트 코퍼스가 없다.** 소급 수집은 삭제·수정된 원문, 부정확한 게시 타임스탬프, 생존 편향 때문에 신뢰할 수 없다.

**② 모델 학습 데이터 오염 — 원리적 장벽.** 상용 LLM 은 특정 시점까지의 웹 텍스트로 학습돼 있다. 과거 구간의 공지·기사를 주고 "이게 호재냐" 를 물으면, 모델은 **그 자산의 이후 가격 흐름을 이미 알고 있을 수 있다.** 이건 코드로 막을 수 있는 종류의 look-ahead 가 아니다.

[[backtest-engine]] 이 막는 look-ahead 와 층위가 다르다는 점이 중요하다. 엔진은 신호를 봉 `i` 종가까지의 window 로 판단하고 체결을 다음 봉 시가로 잡아 **데이터 흐름상의** 미래 참조를 차단한다. 그러나 모델 가중치 안에 들어간 미래 지식은 그 방어를 그냥 통과한다. **엔진이 올바르게 동작해도 결과는 무효다.**

**③ 표본이 부족하다.** 가격을 실제로 움직이는 공지는 마켓당 월 수 건이다. 사실상 단일 마켓·D1 이라는 조건에서는 1년을 모아도 통계적 유의성에 도달하기 어렵다.

## 유일하게 정당한 검증 경로 — 전향적 shadow mode

과거로 갈 수 없으면 앞으로 가는 수밖에 없다. 오염이 **원리적으로 불가능한** 유일한 설계다.

```
텍스트 수집(공지·RSS) → 구조화된 예측 기록 → N일 후 실제 수익률과 대조
```

주문은 내지 않고 예측만 적재한다. 그리고 **측정 지표는 적중률이 아니라 증분(incremental)이다** — LLM 신호가 `combined` 가 이미 잡는 것만 잡는다면 가치는 0 이다. 봐야 할 두 숫자는 이렇다:

- `combined` 가 진입하지 않았는데 LLM 이 맞춘 건수 (신호 추가)
- `combined` 가 진입했는데 LLM 이 걸러냈다면 피했을 손실 (필터 효과)

## 순서 — LLM 없는 baseline 을 먼저 세운다

텍스트에서 알파가 나온다면 그 원천은 "LLM 의 해석"이 아니라 **평소 대비 언급량·톤의 이례성**일 가능성이 높다. 그리고 언급량 이례성 탐지는 카운트와 z-score 로 된다 — LLM 이 필요 없다.

1. 티커별 언급량 카운트 → 이례성 → 수익률 상관 측정 (LLM 비용 0)
2. 1이 유의미할 때만, LLM 으로 방향·근거를 부착하고 **1 대비 증분**을 측정

**1단계를 건너뛰고 LLM 부터 얹으면 어느 쪽이 기여했는지 영원히 귀속할 수 없다.** 그것이 정확히 [[rightsizing-history]] 가 기록한 기각 사유("수익 기여가 입증되지 않은 채 유지비만 발생")의 재현이다. 순서를 지키면 최악의 경우에도 "언급량은 무의미하다"는 확정 사실이 남는다.

기사 크롤링으로 표본을 늘리는 변형은 ③을 완화하지만 ②는 그대로이고, **후행성**이라는 별도 문제가 붙는다 — 시황 기사는 대개 가격이 움직인 *뒤* 나오므로 사후 설명이지 예측 정보가 아니다. 언론사 원문 크롤링은 법적으로도 회색지대이므로 RSS·공식 API 경로로 제한한다.

## 실험을 붙일 때의 격리 조건

- **별도 프로세스로 분리하고 주문 API 권한을 주지 않는다.** 검증되지 않은 코드가 실거래 경로에 들어가면 "미입증 + 유지비"라는 기각 당시 상태를 그대로 재현한다.
- **기존 봇과 같은 인스턴스에 얹지 않는다.** 소형 인스턴스에 프로세스를 늘렸다가 부팅 자체가 막힌 전례가 있다([[lesson-ec2-sizing-oom]]).
- **구독 요금제 토큰으로는 돌릴 수 없다.** Anthropic Consumer Terms 는 API 키 경로 또는 별도 허용을 제외하고 "bot, script, or otherwise" 를 통한 자동·비인간 접근을 금지한다. 무인 서버 에이전트는 API 키(종량 과금)여야 하며, 구독과는 별개 비용이다.

## 표본 확대가 선행 조건이다

③(표본 부족)은 LLM 고유의 문제가 아니라 이 시스템 전체의 제약이고, [[strategy-evolution-expectations]] 가 이미 같은 곳을 가리킨다 — 더 빠른 성장을 원하면 루프를 정교화할 게 아니라 전략 클래스·타임프레임·마켓 폭·투자 사이즈로 **표본을 늘려야** 한다.

즉 **마켓 폭 확대가 LLM 실험의 선행 조건**이다. 표본이 나오지 않는 상태에서 shadow mode 를 돌리면, 몇 달 뒤에 얻는 것은 결론이 아니라 "표본이 부족해 판정 유보"다.
